# 使用說明

這是內建頁面，不是筆記。它讀的是專案裡的靜態檔案，不會存進資料庫，也不能刪除、釘選或改名。

> [!TIP]
> 第一次使用可以先看下面的「60 秒開始」；其餘章節是需要時再回來查的參考手冊，不必一次讀完。

## 60 秒開始

| 想做什麼 | 最快方式 |
|---|---|
| 建立筆記 | 左側欄「新增筆記」，第一行輸入 `# 標題` |
| 開始寫作 | 直接輸入；停止約一秒後自動儲存 |
| 連結另一篇 | 輸入 `[[`，搜尋並插入筆記標題 |
| 快速切換 | `⌘P` 搜尋標題，Enter 開啟 |
| 專心寫／讀 | `⌘⇧F` 進入專注模式，再用 `⌘1`／`⌘2`／`⌘3` 切換檢視 |
| 帶走資料 | 設定 → 匯出全部筆記；單篇 PDF 在筆記右上角 `⋯` 裡 |

### 搜尋功能怎麼選

| 目的 | 使用方式 |
|---|---|
| 搜尋整個筆記庫的標題與內容 | 左側筆記列表上方的搜尋框 |
| 依標題快速開啟或切換筆記 | `⌘P` Quick Open |
| 搜尋目前這一篇的文字 | `⌘F` |
| 插入通往另一篇筆記的連結 | 在 Editor 輸入 `[[` |

## 方案與額度

目前只有一種方案：**NEXUM Scholar Free**，側邊欄左下角那張卡顯示的就是它。

`100 篇`是自己給自己的提醒，不是系統限制 —— 真正的天花板來自 Supabase 免費方案的
500 MB 資料庫與 1 GB 儲存空間。筆記本身很小，會先滿的通常是圖片；`設定 → 匯出全部筆記`
可以隨時把所有內容與附件打包帶走。

**沒有付費方案，也沒有要賣你東西。** 那張卡的「升級方案」連到的就是這一節。

## 筆記

| 動作 | 怎麼做 |
|---|---|
| 新增 | 左側欄的「新增筆記」 |
| 搜尋 | 筆記列表上方的輸入框（左側欄的「搜尋筆記」會把游標送過去）。中文可以搜任何片段，不必是完整詞 |
| 標籤篩選 | 點左側欄的標籤。網址會帶上 `?tag=`，可以加書籤 |
| 只看釘選 | 左側欄的「釘選」。網址是 `?pinned=1`，一樣可以加書籤 |
| 釘選 | 標題列右邊的 `⋯` →「釘選」，或列表的右鍵選單。釘選的排在列表最上面 |
| 刪除 | 標題列右邊的 `⋯` →「移至垃圾桶」。是軟刪除，還原得回來 |
| 還原 | 左側欄「垃圾桶」→ 該篇的「還原」 |

標題不用另外填：**內文第一行的 `# 標題` 就是列表上顯示的名稱**，也會即時顯示在編輯區最上方。
沒寫標題的話會取前幾個字當預覽。

垃圾桶裡的筆記 30 天後由排程真的刪掉，**連同那篇用到的圖片**；滿 30 天之前隨時還原得回來。

### 標籤

標籤在**標題下方**，跟標題一樣屬於「這篇是什麼」，不是內文的一部分 —— 它存在資料庫欄位，
**不會寫進 Markdown**，所以匯出的 `.md` 乾乾淨淨（標籤會寫進匯出檔開頭的 frontmatter）。

| 動作 | 怎麼做 |
|---|---|
| 加標籤 | 標題下方的輸入框打字後按 Enter，會自動完成既有標籤 |
| 移除 | 點標籤右邊的 `×`，或輸入框空著時按退格 |
| 從列表加 | 筆記列表右鍵 →「新增標籤／編輯標籤」，會開啟筆記並把游標放進標籤欄 |
| 改名 | 左側欄的標籤上**按右鍵** →「重新命名」，原地改字，Enter 確認 |
| 刪除標籤 | 左側欄標籤右鍵 →「刪除標籤」。**只刪標籤，筆記一篇都不會動** |

改名時如果打成一個已經存在的標籤，兩個會**合併**成同一個，不會跳錯誤。

### 右鍵選單

在列表的任一列上**按右鍵**，或滑上去點右上角的 `⋯`，兩個入口開的是同一個選單：

| 項目 | 說明 |
|---|---|
| 開啟 | 等同點那一列 |
| 釘選／取消釘選 | 釘選的排在列表最上面 |
| 複製 Markdown | 整篇原始語法複製到剪貼簿 |
| 匯出 Markdown | 單獨下載這一篇的 `.md`（`設定 → 匯出全部筆記`才是全部打包） |
| 移至垃圾桶 | 軟刪除，還原得回來。這裡沒有「永久刪除」 |

`Esc` 或點外面關閉，上下鍵可以在項目間移動。從列表刪別篇筆記時，不會把你踢出正在編輯的那篇。

## 分頁

工作區上方是開過的筆記，點一下切回去。這一頁（使用說明）也是一個分頁。

| 操作 | 行為 |
|---|---|
| 點列表裡的筆記 | 已經開著就切過去，沒開過就新增一個分頁 |
| `×` 或滑鼠中鍵 | 關閉。關掉的是目前這篇時，跳去左邊那個 |
| 右鍵分頁 | 關閉／關閉其他分頁 |
| 重新整理 | 分頁列會還原 |

分頁右邊有一個**小點代表還沒存完**。切分頁不用等它 —— 切走的當下沒送出的內容會補存。

分頁列記在這台電腦的瀏覽器裡（不進資料庫），所以換一台電腦開會是空的，清瀏覽器資料也會清掉。

## 知識連結與快速開啟

在 Markdown 裡直接寫 `[[筆記標題]]`。輸入 `[[` 後會出現自動完成；可以繼續打中文篩選，
用上下鍵選、Enter 插入、Esc 關閉。程式碼區塊與行內 code 裡的同樣文字只會當原文。

- 預覽中可找到唯一同名筆記時，點連結會用既有分頁開啟它。
- 找不到時會先問你是否建立精確同名的新筆記，不會單點就偷偷建立。
- 若已有多篇同名筆記，v1 的 `[[Title]]` 無法安全區分，會保持未解析，不會任選第一篇。
- 預覽正文最下方的 **Linked References** 會列出哪些筆記連到目前這篇，並顯示附近內容。
- `⌘P` 開啟 Quick Open；不輸入時是最近開啟，輸入後可搜尋標題並切換既有分頁。Windows／Linux
  使用 `Ctrl+P`。

Markdown 永遠保存可讀的 title，不會改成 UUID；匯出 Markdown、ZIP 或 PDF 時仍看得到
`[[Title]]`。改掉一篇有來源連結的標題時，系統會先要求確認，確認後才一次更新那些精確連結；
任一來源在此期間被別處修改，整批改名都會取消，不留下改一半的結果。「取消改名」只還原標題，
同一批輸入的正文仍會照常儲存。刪除目標不會刪來源文字，還原同標題後會自然重新連上。

目前是 v1，只支援 `[[Title]]`。`[[Title|Alias]]`、章節連結、block reference、內容嵌入與
Knowledge Graph 都還沒有實作；把這些寫法貼進來不會得到 Obsidian 的特殊行為。

## 自動儲存

編輯區右下角一直顯示目前狀態：

| 顯示 | 意思 |
|---|---|
| 已儲存 | 內容跟資料庫一致 |
| 未儲存 | 剛改過，還在等一秒的緩衝 |
| 儲存中… | 正在寫入 |
| 等待確認改名 | 有其他筆記連到舊標題；先選擇是否更新連結並改名 |
| 儲存失敗 | 寫入出錯，會自動重試，也可以手動按「立刻重試」 |
| 有衝突，未儲存 | 這篇**真的**在別的地方被改過（另一個分頁、另一台裝置、或剛還原了版本）。不會自動覆蓋對方，請開新分頁比對後手動合併 |

停止輸入約一秒就會自動存。切換到別篇筆記或關閉分頁時，還沒存的內容會補送一次。

存檔一次只會跑一個，第二次會排隊等前一次回來 —— 所以連續按 `⌘S` 或打字打到一半按存檔
都不會出問題。編輯途中按釘選也不會（那也算一次更新，但系統認得出那是你自己做的）。


## 工具列

每個按鈕滑上去都會顯示名稱與快捷鍵。按功能分四組：復原／重做、文字格式、清單、插入。

**`<>` 程式碼區塊收在最右邊的「更多」裡**，第一層留給備註框 —— 法律筆記幾乎不寫程式碼，
但很常需要圈出考點。

## Slash Command

在一般 Markdown 文字區域的**行首或空白後**輸入 `/`，會開啟快速插入選單。繼續輸入中英文都能
篩選，例如 `/heading`、`/重點`、`/實務`；上下鍵移動、Enter 執行、Esc 關閉，也可以直接用
滑鼠點選。

選單包含 H1／H2／H3、無序與有序清單、待辦、引用、四種備註框、分隔線、表格、圖片與程式碼
區塊。選定後 `/` 與查詢文字會一起被替換，一次 `⌘Z` 就能完整還原。

URL、行內 code、圍欄式 code block、四格縮排的程式碼，以及不合理的文字中間不會跳出選單。
Slash Command 跟 `[[` Wiki Link autocomplete 共用同一套鍵盤操作，但彼此不會搶選單。

## 備註／重點框

`⌘⇧M` 直接插入「重點」，或按工具列的備註框按鈕選一種：

| 類型 | 用途 | 顏色 |
|---|---|---|
| 重點 | 考點與結論 | 金色 |
| 實務見解 | 判決、函釋、通說 | 墨藍 |
| 易錯提醒 | 會扣分的地方 | 紅色 |
| 自我理解 | 自己的話，不是權威來源 | 綠色 |

寫出來的語法長這樣，底層是引用區塊：

```
> [!KEY]
> 客觀與主觀構成要件都該當，才進入違法性判斷。
```

四種類型可用的標記依序是 `KEY`、`PRACTICE`、`PITFALL`、`INSIGHT`。**這是這個工具自訂的**，
匯出到 GitHub 或 Obsidian 會顯示成一般引用，標記那一行會以文字留著 —— 讀得懂，不會壞。

從別處貼過來的 GitHub 五種（`NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION`）照樣認得。

## 大綱

標題列右邊的大綱按鈕會在右側開一欄章節清單，點一下就跳過去 —— 編輯區的游標與預覽區
會**一起**移動。**目前讀到的那一節會標起來**，捲動時跟著換。

只有 `#` 開頭**而且後面有空白**的行才算標題（`#標題` 在 Markdown 裡不是標題，預覽也不會
變大）。程式碼區塊裡的 `#` 註解不會被收進來。

## 專注模式

`⌘⇧F`，或標題列右邊那個框框圖示。左側欄、筆記列表、分頁列全部收起來，整個畫面只剩這一篇。

留下來的是：標題、標籤、工具列、編輯區、預覽區，以及右下角的存檔狀態。

| 想做什麼 | 按什麼 |
|---|---|
| 專心寫 | `⌘⇧F` 之後 `⌘1` —— 編輯器置中成一欄 |
| 對照著寫 | `⌘⇧F` 之後 `⌘2` |
| 專心讀 | `⌘⇧F` 之後 `⌘3` —— 只剩標題與閱讀欄 |

退出用 `⌘⇧F` 或 `Esc`，畫面會回到你進去之前的樣子（分頁一個都不會關，游標與捲動位置
也都還在）。大綱在專注模式裡預設收起，但隨時可以打開。

專注模式記在這台電腦的瀏覽器裡，所以**重新整理之後仍然在專注模式**。

## 三種檢視

編輯區有三種模式，用快捷鍵切換：

- **只看編輯** — 專心寫，不看渲染結果
- **左右分割** — 預設，左邊原始語法、右邊渲染結果
- **只看預覽** — 專心讀

兩欄都限制了行寬：預覽區約 68 個字、編輯區約 74 個字（只看編輯時放寬一點並置中）。
大螢幕上整行拉到底只會讓眼睛從行尾找不回行首，這是教科書與電子書的行寬慣例。

**左右分割時兩欄會一起捲。** 對齊是用標題當基準，所以標題愈多對得愈準；捲哪一邊都可以。

只看預覽時工具列會收起來 —— 那時候沒有編輯器可以操作。

## 快捷鍵

以下都是目前真的可用的。

| 按鍵 | 動作 |
|---|---|
| `⌘1` / `⌘2` / `⌘3` | 只看編輯／左右分割／只看預覽 |
| `⌘P` | Quick Open：最近開啟、搜尋並切換筆記 |
| `⌘\` | 收合／展開左側欄（收合後仍留一排圖示，滑上去有說明） |
| `⌘S` | 立刻儲存（平常已自動存，這個是求心安用的） |
| `⌘B` | 粗體 |
| `⌘I` | 斜體 |
| `⌘K` | 插入連結，游標會落在網址的括號裡 |
| `⌘⇧C` | 程式碼區塊 |
| `⌘⇧I` | 插入圖片 |
| `⌘⇧H` | 螢光筆（黃色） |
| `⌘⇧M` | 備註框（重點） |
| `⌘⇧F` | 專注模式 |
| `⌘F` | 在目前這篇筆記內搜尋（CodeMirror 內建） |
| `⌘Z` / `⌘⇧Z` | 復原／重做 |
| `Tab` / `⇧Tab` | 縮排／反縮排，行為見下一節 |

## Tab 與縮排

`Tab` 縮一層、`⇧Tab` 退一層。選取多行就整段一起縮或退，`⌘Z` 復原得回來。

**縮排單位會看你在哪一種行上**：

| 這一行 | Tab 插入 |
|---|---|
| 清單、待辦、有序清單、空行 | 半形兩格 —— 那是 Markdown 的巢狀語法 |
| 一般段落、中文條列（`一、`、`（一）`） | 一個**全形空格** |

為什麼分兩種：**行首的半形空白在 Markdown 裡不算內容，渲染時會被吃掉** —— 左邊看得到
層次，右邊卻是平的。全形空格是普通字元，所以兩邊長得一樣，匯出的 `.md` 在別的編輯器
裡也一樣有縮排。

代價是原始碼裡有看不見的全形空格；左右兩邊的縮排寬度也不會完全相等（等寬字體兩格寬
對上襯線字體約一個中文字寬）。

**縮排參考線** — 每一層縮排的起點有一條淡線，數層數不用再自己算空白。

### 四個空白 = 程式碼區塊

Markdown 標準規定**行首四個半形空白代表程式碼區塊**（indented code block）。一旦觸發：

- 整段被框起來，右上角會標示「程式碼」
- 裡面的內容變成原始文字，`==螢光標記==`、`**粗體**` 全部失效
- 這是正確的 Markdown 語意，不是 bug

`Tab` 不會讓你踩到這個 —— 一般段落插的是全形空格，不算數。但**手打或從別處貼進來的
四個空白會**。真的要寫程式碼請用下面的圍欄式區塊，那個不受縮排影響。

## 中文條列

法律筆記常用的公文層級編輯器都認得，按 Enter 會自動接下一項：

| 目前這行 | 按 Enter |
|---|---|
| `一、意義` | 產生 `二、` |
| `（九）第九點` | 產生 `（十）` |
| `（1）要件` | 產生 `（2）` |
| `甲、學說` | 產生 `乙、` |
| `A、第一點` | 產生 `B、` |
| `三、`（沒有內容） | 清掉標記，跳出條列 |

中文數字支援一到九十九、阿拉伯數字到 99、天干到「癸」、字母到 Z，走完就當一般換行。
`X、` 與 `（X）` 兩種寫法都通用，只有阿拉伯數字限定 `（1）` —— `1、` 在中文裡是並列
（「3、4 月間」），接手會誤判；而 `1.` 是 Markdown 自己的有序清單，本來就會延續。

中文輸入法常會產生全形數字、全形句點或省略句點後的空白。編輯器也接受下列常見形式：

| 輸入 | 按 Enter 後 |
|---|---|
| `1.第一點` | `2. ` |
| `1．第一點` | `2. ` |
| `１. 第一點` | `2. ` |
| `１．第一點` | `2. ` |
| `1.　第一點`（全形空格） | `2. ` |

延續時會正規化成 CommonMark 的半形 `2. `，所以 Preview、Markdown 與其他編輯器都讀得懂。
一般中文段落、版本號、小數與四格縮排的程式碼不會被誤判成清單。

行首的縮排會沿用，**全形空格也算**。半形的 `(一)`、`(1)` 不接手，避免誤判。
`（１）` 這種全形數字與小寫的 `a、` 都會照原本的寫法接下去。

延續時會在上一行尾巴補兩個空白，這是 Markdown 的**硬換行**寫法 —— 少了它，預覽會把
`一、意義` 跟 `二、要件` 接成同一行。

這產生的是**純文字**，不是特殊語法 —— 匯出的 `.md` 在任何編輯器裡都跟你看到的一樣。

## Markdown 語法

| 語法 | 結果 |
|---|---|
| `# 標題` 到 `###### 標題` | 六級標題 |
| `**粗體**` | **粗體** |
| `*斜體*` | *斜體* |
| `==螢光標記==` | 黃色螢光筆 |
| `==文字=={g}` | 綠色。另有 `{p}` 粉、`{b}` 藍 |
| `- 項目` | 項目清單 |
| `1. 項目` | 編號清單 |
| `- [ ] 項目` | 待辦清單 |
| `> 引用` | 引用 |
| `[文字](網址)` | 連結 |
| `![說明](網址)` | 圖片 |
| `` `行內程式碼` `` | 行內程式碼 |
| `---` | 水平分隔線 |

表格：

```
| 欄位 | 欄位 |
| --- | --- |
| 內容 | 內容 |
```

重點區塊：

```
> [!NOTE]
> 提示內容
```

常用的四種是 `KEY` 重點、`PRACTICE` 實務見解、`PITFALL` 易錯提醒、`INSIGHT` 自我理解（見上面的「備註／重點框」）。GitHub 的 `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 也認得。底層都是引用區塊，匯出到別的編輯器至少會顯示成引用，不會變成亂碼。

## 圖片與附件

直接把圖片**貼上或拖進編輯區**就會自動上傳，先出現「上傳中…」的佔位文字，完成後換成圖片連結。也可以用工具列的圖片按鈕選檔案。

- 上傳前會在瀏覽器端壓縮並轉成 WebP，長邊超過 2000 會等比例縮小
- GIF 與 SVG 原樣上傳（轉檔會讓它們變糟）
- 單檔上限 10 MB
- 圖片放在公開的儲存空間，檔名是隨機 UUID。**網址猜不到，但拿到網址的人就看得到 —— 真正機密的東西不要放**

## 版本快照

右上角的時鐘圖示打開版本紀錄。

- 每 10 分鐘留一份，每篇最多 30 份
- 存的是**改動前**的內容，所以整篇刪光之後仍然回得去
- 按「還原」之前，系統會先把當下的內容也存成一份，按錯了還能回來

## 匯出

### 匯出全部筆記

左側欄底部的 `設定 → 匯出全部筆記` 會把全部筆記打包成 ZIP 下載：

- `notes/` 與 `trash/` 兩個資料夾，每篇一個 `.md`
- 檔案開頭是 YAML frontmatter，記錄標題、標籤與時間，Obsidian 和 Typora 讀得懂
- 內文的圖片網址會改寫成 `../attachments/` 相對路徑，附件一併打包 —— 不需要網路也不需要這個服務就看得到圖

### 單篇 Markdown 與 PDF

- 筆記列表右鍵可「複製 Markdown」或「匯出 Markdown」。
- 目前筆記右上角 `⋯ → 匯出 PDF` 會在新分頁開啟 A4 預覽。
- PDF 預覽可選 **Study**（保留低飽和語義色）或 **Clean**（接近黑白正式文件）。
- 確認內容後按「列印 / 儲存 PDF」，在瀏覽器列印視窗選擇「儲存為 PDF」。

Wiki Links 在 Markdown／ZIP 中維持可讀的 `[[Title]]`；PDF 會顯示 title 文字，但不會輸出
Quick Create 按鈕、tooltip 或只能在 NEXUM NOTE 裡使用的互動控制。
