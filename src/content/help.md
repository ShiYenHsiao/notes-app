# 使用說明

這是內建頁面，不是筆記。它讀的是專案裡的靜態檔案，不會存進資料庫，也不能刪除、釘選或改名。

## 筆記

| 動作 | 怎麼做 |
|---|---|
| 新增 | 左側欄的「＋ 新增筆記」 |
| 搜尋 | 筆記列表上方的輸入框。中文可以搜任何片段，不必是完整詞 |
| 標籤篩選 | 點左側欄的標籤。網址會帶上 `?tag=`，可以加書籤 |
| 釘選 | 編輯畫面右上角的圖釘。釘選的排在列表最上面 |
| 刪除 | 右上角的垃圾桶圖示。是軟刪除，進垃圾桶還原得回來 |
| 還原 | 左側欄「垃圾桶」→ 該篇的「還原」 |

標題不用另外填：**內文第一行的 `# 標題` 就是列表上顯示的名稱**。沒寫標題的話會取前幾個字當預覽。

垃圾桶裡的筆記 30 天後自動清除。

## 自動儲存

編輯區右下角一直顯示目前狀態：

| 顯示 | 意思 |
|---|---|
| 已儲存 | 內容跟資料庫一致 |
| 未儲存 | 剛改過，還在等一秒的緩衝 |
| 儲存中… | 正在寫入 |
| 儲存失敗 | 寫入出錯，會自動重試，也可以手動按「立刻重試」 |
| 有衝突，未儲存 | 這篇在別的地方被改過（通常是自己開了兩個分頁）。不會自動覆蓋對方 |

停止輸入約一秒就會自動存。切換到別篇筆記或關閉分頁時，還沒存的內容會補送一次。

## 三種檢視

編輯區有三種模式，用快捷鍵切換：

- **只看編輯** — 專心寫，不看渲染結果
- **左右分割** — 預設，左邊原始語法、右邊渲染結果
- **只看預覽** — 專心讀

## 快捷鍵

以下都是目前真的可用的。

| 按鍵 | 動作 |
|---|---|
| `⌘1` / `⌘2` / `⌘3` | 只看編輯／左右分割／只看預覽 |
| `⌘\` | 收合／展開左側欄 |
| `⌘S` | 立刻儲存（平常已自動存，這個是求心安用的） |
| `⌘B` | 粗體 |
| `⌘I` | 斜體 |
| `⌘K` | 插入連結，游標會落在網址的括號裡 |
| `⌘⇧C` | 程式碼區塊 |
| `⌘⇧H` | 螢光筆（黃色） |
| `⌘F` | 在目前這篇筆記內搜尋（CodeMirror 內建） |
| `⌘Z` / `⌘⇧Z` | 復原／重做 |
| `Tab` / `⇧Tab` | 縮排／反縮排，行為見下一節 |
| `Enter` | 在清單裡自動延續項目與編號；在空項目上再按一次就跳出清單 |

瀏覽器保留了 `⌘N`、`⌘T`、`⌘W`，網頁攔不到，所以新增筆記只能用畫面上的按鈕。

## Tab 與縮排

這一節值得看仔細，因為 Markdown 有一條容易踩到的規則。

**在清單裡** — `Tab` 增加一層、`⇧Tab` 減少一層。有序清單的編號不會被打亂。

**選取多行時** — `Tab` 整段一起縮、`⇧Tab` 整段一起退。可以用 `⌘Z` 復原。

**在一般段落** — `Tab` 縮一層（兩個空白）。但**行首滿四個空白時會被擋下來並跳出提示**。

為什麼要擋：Markdown 標準規定**行首四個空白代表程式碼區塊**（indented code block）。一旦觸發：

- 整段被框起來，右上角會標示「程式碼」
- 裡面的內容變成原始文字，`==螢光標記==`、`**粗體**` 全部失效
- 這是正確的 Markdown 語意，不是 bug

所以想做視覺層次請用清單或引用，想寫程式碼請用下面的圍欄式區塊 —— 那個不受縮排影響。

## 中文條列

法律筆記常用的「一、」「（一）」編輯器認得，按 Enter 會自動接下一項：

| 目前這行 | 按 Enter |
|---|---|
| `一、意義` | 產生 `二、` |
| `（九）第九點` | 產生 `（十）` |
| `三、`（沒有內容） | 清掉標記，跳出條列 |

支援一到九十九。行首的縮排會沿用，**全形空格也算**。半形的 `(一)` 不接手，避免誤判。

這產生的是**純文字**，不是特殊語法 —— 匯出的 `.md` 在任何編輯器裡都跟你看到的一樣。

## Markdown 語法

| 語法 | 結果 |
|---|---|
| `# 標題` 到 `###### 標題` | 六級標題 |
| `**粗體**` | **粗體** |
| `*斜體*` | *斜體* |
| `==螢光標記==` | 黃色螢光筆 |
| `==文字=={g}` | 綠色。另有 `{p}` 粉、`{b}` 藍 |
| `- 項目` | 項目清單 |
| `1. 項目` | 編號清單 |
| `- [ ] 項目` | 待辦清單 |
| `> 引用` | 引用 |
| `[文字](網址)` | 連結 |
| `![說明](網址)` | 圖片 |
| `` `行內程式碼` `` | 行內程式碼 |
| `---` | 水平分隔線 |

表格：

```
| 欄位 | 欄位 |
| --- | --- |
| 內容 | 內容 |
```

圍欄式程式碼區塊 —— 用三個反引號包起來，**這是寫程式碼的正確方式**：

```
```
程式碼放這裡
```
```

重點區塊：

```
> [!NOTE]
> 提示內容
```

可用的類型有 `NOTE` 提示、`TIP` 訣竅、`IMPORTANT` 重要、`WARNING` 注意、`CAUTION` 警告。這是 GitHub 的語法，底層仍是引用區塊，所以匯出到別的編輯器至少會顯示成引用，不會變成亂碼。

## 圖片與附件

直接把圖片**貼上或拖進編輯區**就會自動上傳，先出現「上傳中…」的佔位文字，完成後換成圖片連結。也可以用工具列的圖片按鈕選檔案。

- 上傳前會在瀏覽器端壓縮並轉成 WebP，長邊超過 2000 會等比例縮小
- GIF 與 SVG 原樣上傳（轉檔會讓它們變糟）
- 單檔上限 10 MB
- 圖片放在公開的儲存空間，檔名是隨機 UUID。**網址猜不到，但拿到網址的人就看得到 —— 真正機密的東西不要放**

## 版本快照

右上角的時鐘圖示打開版本紀錄。

- 每 10 分鐘留一份，每篇最多 30 份
- 存的是**改動前**的內容，所以整篇刪光之後仍然回得去
- 按「還原」之前，系統會先把當下的內容也存成一份，按錯了還能回來

## 匯出

左側欄底部的「匯出」會把全部筆記打包成 zip 下載：

- `notes/` 與 `trash/` 兩個資料夾，每篇一個 `.md`
- 檔案開頭是 YAML frontmatter，記錄標題、標籤與時間，Obsidian 和 Typora 讀得懂
- 內文的圖片網址會改寫成 `../attachments/` 相對路徑，附件一併打包 —— 不需要網路也不需要這個服務就看得到圖

## 手機與 iPad

行動裝置是**唯讀**的，只顯示渲染後的內容，不載入編輯器。設計上就是這樣：編輯在 Mac 上做，手機用來查。

可以把網址加到主畫面當 App 用。
