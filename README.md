# 筆記工具

跨裝置的個人筆記程式。目前尚未開始實作，以下是已確定的方向。

編輯體驗以 HackMD 為參考：**Mac 是唯一的編輯環境，手機與 iPad 只用來閱讀**。這個前提貫穿下面所有設計決策。

## 基礎架構

| 項目 | 決定 |
|---|---|
| 同步方式 | 雲端資料庫 + 部署到 Vercel，任何裝置開網址就能用 |
| 後端服務 | Supabase — Postgres（筆記）、Storage（附件）、Auth（登入）三者共用一個免費方案 |
| 前端框架 | Next.js（App Router），部署零設定，後端邏輯直接寫在 Server Actions |
| 登入方式 | Supabase Auth，單人帳號（Magic Link 或 GitHub OAuth）；架構上仍保留多使用者的可能 |
| 離線行為 | 線上為主，離線唯讀 — 快取已讀過的筆記供離線查看，編輯需要連線 |

## 編輯體驗

| 項目 | 決定 |
|---|---|
| 編輯模式 | **左右分割即時預覽**（HackMD 風格）：左邊純 Markdown 原始語法，右邊渲染結果，兩邊捲動同步 |
| 標題 | 內文第一行的 `# 標題` 自動當作列表顯示名稱；沒寫標題就取前幾個字當預覽 |
| 存檔 | 停止輸入約一秒自動存檔 |
| 版本快照 | 每 10 分鐘留一份，每篇最多 30 份。存的是「存檔前」的內容 — 快照要記錄的是回得去的狀態，存後才留的話把整篇刪光再存，快照裡就只剩空字串。還原前會先把當下內容也存一份，按錯了回得去 |
| 存檔狀態 | 編輯區固定位置顯示「儲存中／已儲存／儲存失敗」，失敗時明顯提示並自動重試。斷線時切換成唯讀並說明原因 |
| 編輯輔助 | 完整工具列（粗體、斜體、清單、連結、圖片、表格、程式碼區塊…）+ 快捷鍵並行 |
| 圖片與附件 | 貼上或拖曳即自動上傳到 Supabase Storage，左邊插入 `![](網址)`、右邊預覽區直接看到圖。上傳中先放佔位文字，完成後換成網址 |
| 圖片壓縮 | 上傳前在瀏覽器端壓縮並轉成 WebP，超過一定尺寸的縮到合理長邊。手機截圖動輒 2–3 MB，不壓的話 1 GB 額度貼幾百張就滿了 |
| 組織方式 | 純標籤，不做資料夾；常用筆記可釘選到列表最上方 |
| 標籤輸入 | 編輯區下方獨立的標籤列（chip + 自動完成），標籤存在資料庫欄位，不寫進 Markdown 內文 |
| 刪除 | 軟刪除進垃圾桶可還原，30 天後自動清除（附件也在此時一併回收） |
| 匯出 | 一鍵把全部筆記匯成 `.md` 檔 + 附件打包下載。免費方案有被砍或漲價的風險，這是資料不被綁死的保險 |

## 介面

**桌機（主力）— 三欄**

```
┌──────────┬────────────────┬─────────────────────────────┐
│ 標籤     │ 筆記列表        │  編輯區                      │
│ ─────    │ ────────       │  ┌───────────┬─────────────┐ │
│ 釘選     │ [搜尋框]        │  │ Markdown  │  預覽        │ │
│ #專案    │ 筆記 A         │  │ 原始語法   │  渲染結果    │ │
│ #讀書    │ 筆記 B         │  │           │             │ │
│ 垃圾桶   │ 筆記 C         │  └───────────┴─────────────┘ │
│          │                │  [標籤列]      [已儲存]      │
└──────────┴────────────────┴─────────────────────────────┘
   可摺疊         可摺疊        兩欄都摺起來 = 專注模式
```

搜尋有兩個入口：筆記列表上方的常駐搜尋框，以及命令面板（搜尋、跳轉、新增筆記、切換主題都從這裡走）。

**桌機預設欄寬**：側邊欄 216px、筆記列表 288px、主工作區吃剩下的空間；分割模式下編輯區與
預覽區各 `flex-1 basis-1/2`。兩欄都加 `min-w-0` —— flex 項目的預設 `min-width` 是 `auto`，
少了它，長網址或寬表格會撐開欄位而讓整頁出現水平捲軸。目前沒有拖曳調整寬度的功能。

側邊欄自己是 flex column：中段（導覽與標籤）獨立捲動，底部的主題切換與匯出／登出
`shrink-0` 永遠看得見。

**Next.js 的開發指示器**預設在左下角，正好壓住側邊欄底部那排控制項。它由框架繪製在我們的
React 樹之外，沒辦法放進 sidebar，只能選四個角落，所以在 `next.config.ts` 改成 `bottom-right`。
production build 不會出現它。

### 內建使用說明

左側欄有一個固定的「使用說明」入口（`/help`），內容來自
[`src/content/help.md`](src/content/help.md)，由 Server Component 讀檔後用同一套
`MarkdownPreview` 渲染。

**刻意不存進 Supabase**：它是程式的一部分而不是使用者的資料，跟著版本走才對。存成一筆
notes 的話會多出一篇能被刪除、釘選、改名、混進搜尋結果的假筆記，而且每次改文案都要寫
migration。放在 repo 裡則是改完 deploy 就更新，也不佔資料庫額度。

**手機 / iPad（唯讀）— 兩層導覽**

- 第一層筆記列表，點進去第二層全螢幕閱讀，左滑或返回鍵退出。
- 只顯示渲染後的內容，不提供編輯介面，也不載入編輯器套件。
- 可加到主畫面當 PWA 用。

**視覺風格**

- 溫暖紙感：偏米黃的底色、襯線字體、較寬的行高，適合長時間閱讀與寫作。
- 深色主題另外調整，不是把淺色直接反相 — 底色用暖調的深棕灰而非純黑，維持同樣的紙感。
- 底色分四層：側邊欄 → 筆記列表 → 頁面 → 編輯區，每層都要看得出差別，不能只靠分隔線撐。
- 側邊欄有「淺／深／自動」切換。**「自動」跟的是瀏覽器的外觀設定，不是作業系統** — Chrome 可以自己設成深色而蓋掉系統設定，這正是需要手動選項的原因。
- 色票用 CSS 的 `light-dark()` 寫成單一來源，不要淺色深色各維護一份。
- 程式碼區塊仍用等寬字體，與內文的襯線字體形成對比。
- 字體只從 Google Fonts 載入拉丁文襯線體（Source Serif 4），中文交給系統內建的 Songti TC。Noto Serif TC 這類 CJK webfont 動輒好幾 MB，對一個個人工具不划算 — 反正 Mac 與 iOS 都內建襯線中文字。

## 快捷鍵

`Cmd+K` 在絕大多數 Markdown 編輯器裡是「插入連結」，肌肉記憶很強，所以命令面板改用 `Cmd+P`。

| 按鍵 | 動作 |
|---|---|
| `Cmd+P` | 命令面板：搜尋、跳轉筆記、新增筆記、切換主題（**尚未實作**，目前搜尋只有列表上方的常駐輸入框） |
| `Cmd+F` | 在目前這篇筆記內搜尋（CodeMirror 內建） |
| `Cmd+S` | 立即存檔（平常已自動存，這個是求心安用的） |
| `Cmd+B` / `Cmd+I` | 粗體／斜體 |
| `Cmd+K` | 插入連結 |
| `Cmd+Shift+C` | 程式碼區塊 |
| `Cmd+Shift+I` | 插入圖片（開檔案選擇器） |
| `Cmd+1` / `Cmd+2` / `Cmd+3` | 只看編輯／左右分割／只看預覽 |
| `Cmd+\` | 摺疊／展開側邊欄 |
| `Cmd+Shift+H` | 螢光筆（黃色） |
| `Tab` / `Shift+Tab` | 縮排／反縮排，規則見下節 |
| `Esc` | 關閉命令面板、退出專注模式 |

### Tab 與 indented code block

CommonMark 規定**行首四個空白就是程式碼區塊**（indented code block）。一旦觸發，整段變成
literal text，`==螢光標記==` 與 `**粗體**` 全部失效。這是標準行為，不是 bug，所以不用
CSS 或改 renderer 去掩蓋。

Tab 的行為因此分三種（判斷規則在 [`src/lib/indent-rules.ts`](src/lib/indent-rules.ts)）：

| 情境 | 行為 |
|---|---|
| 清單項目、空行 | 照 CodeMirror 標準縮排，一層兩格。清單縮排不會觸發程式碼區塊 |
| 跨行選取 | 整段一起縮／退，可 `Cmd+Z` 復原 |
| 一般段落 | 縮一層；**行首要滿四個空白時擋下來並顯示提示**，不讓它靜默變成程式碼區塊 |

選擇「擋下並提示」而不是插入不可見字元或自訂語法，是因為它完全不偏離標準 Markdown、
匯出的 `.md` 在任何編輯器裡都一樣，而且 ` ``` ` 圍欄式程式碼區塊照常可用。

提示只出現在介面上，不會寫進筆記內容。

### 清單與段落的銜接

CommonMark 對「清單能不能打斷段落」有兩條限制，兩條都很容易踩到：

1. **第一個項目不能是空的。** 剛打完 `1. ` 還沒輸入內容時，那一行仍然是段落文字 ——
   這就是「打 `1.` 預覽沒變成清單」的真正原因。
2. **有序清單只有從 1 開始才能打斷段落。** `2. 甲` 接在段落後面不會變成清單。

兩條都是標準行為（`tests/markdown.test.mjs` 有對應測試）。與其要求使用者背規則，
編輯器在**普通段落後面建立清單時自動補一行空行** —— 那本來就是人手寫 Markdown 會做的事，
補完之後兩條限制都不再適用。

補插的時機有兩個，都跟原本的改動放在**同一個 transaction**，所以 `Cmd+Z` 一次退回：

- 手打清單標記後按空白鍵（`EditorView.inputHandler`）
- 工具列的三個清單按鈕（`toggleLinePrefix`）

上一行若是空行、清單、引用、標題、圍欄或表格就不補 —— 那些本來就是獨立區塊。

Enter 的清單延續、空項目退出清單、Backspace 刪除標記，全部由 CodeMirror 官方的
`markdownKeymap` 處理（`markdown()` 預設就會掛上），沒有自訂實作。

### 中文條列

法律筆記的層級慣例是「一、二、三、」配「（一）（二）（三）」，Markdown 沒有對應語法，
所以這一層完全在編輯器處理（[`src/lib/chinese-list.ts`](src/lib/chinese-list.ts)）：

| 行內容 | 按 Enter 之後 |
|---|---|
| `一、意義` | 新增一行 `二、` |
| `（九）第九點` | 新增一行 `（十）` |
| `十九、甲` | 新增一行 `二十、` |
| `三、`（空項目） | 清掉標記，跳出條列 |

- 支援一到九十九，超出範圍就當一般換行
- 行首縮排與標記後的空白會沿用，**含全形空格 U+3000** —— 中文筆記很常用它做層次
- 半形括號 `(一)` 不接手，避免誤判程式碼或英文內容
- 游標不在行尾、或有選取範圍時不接手

**產生的是純文字**，不是自訂語法，所以匯出的 `.md` 在任何編輯器裡都跟原本一樣，
Markdown 可攜性不受影響。

實作上這個 keymap 是 `Prec.highest`，才排得到官方 `markdownKeymap`（`Prec.high`）前面；
不是中文條列時回傳 `false` 交還給它，Markdown 清單的行為完全不變。

注意瀏覽器保留了 `Cmd+N`、`Cmd+T`、`Cmd+W`，網頁攔不到，所以「新增筆記」只能走命令面板或畫面上的按鈕，不要指望快捷鍵。

## 技術架構

```
瀏覽器 (PWA)  ──►  Next.js on Vercel  ──►  Supabase
   │                (Server Actions)        ├─ Postgres  筆記、標籤、版本
   └─ Service Worker                        ├─ Storage   圖片與附件
      快取已讀筆記（唯讀）                    └─ Auth      登入
```

**搜尋**用 `pg_trgm` 擴充建 GIN 索引，配 `ILIKE` 查詢。**不用** Postgres 內建的 tsvector 全文搜尋 — 它的預設斷詞器不處理中文，會把整句中文當成單一 token，導致搜「資料庫」找不到內容裡的「資料庫設計」。中文斷詞得靠 `zhparser` 之類的擴充，在託管環境上不一定裝得了。trigram 對中文的行為正確，幾千篇筆記的規模也完全不會慢；代價是沒有相關度排序，結果依更新時間排。

**附件**放公開 bucket，檔名用隨機 UUID。網址猜不到，但拿到就看得到 — 個人筆記的圖片通常不敏感，換來的是預覽區直接引用、CDN 快取有效，而且匯出的 `.md` 檔在別的編輯器裡打開圖片照樣顯示（簽名網址會過期，匯出檔就廢了）。**要放真正敏感的東西時別用附件功能。**

其他：

- 資料表以 `user_id` 做列級安全性（RLS），即使目前只有一個帳號也照樣設定，之後要開放他人使用不用改架構。
- 編輯器只在桌機版載入，行動版走另一條輕量的閱讀路徑，避免把整包編輯器塞進手機。
- 存檔時用 `updated_at` 做樂觀鎖。單人也會在 Mac 上開兩個分頁編同一篇，沒有這道防線的話自動存檔會互相蓋掉；偵測到衝突就擋下來並提示，不要默默覆蓋。
- Supabase 免費方案：500 MB 資料庫、1 GB 儲存空間，個人使用足夠；但專案長時間無活動會被暫停，登入後可恢復，長期使用前要留意。

## 資料模型

完整定義在 [`supabase/migrations/`](supabase/migrations/)。

```
notes       id, user_id, content, title, pinned,
            created_at, updated_at, deleted_at
tags        id, user_id, name
note_tags   note_id, tag_id
versions    id, note_id, content, created_at
attachments id, note_id, storage_path, filename, size, mime_type, created_at
```

幾個實作上的決定：

- `notes.title` 是 generated column，由資料庫從內文第一行推導（去掉開頭的 `#`），不是另外存一個會跟內文不同步的欄位。標題為空時是 `null`，前端改用內文摘要顯示。
- 標籤用 `note_tags` 關聯表而非 `text[]` 陣列欄位 — 改標籤名只要改一個地方，自動完成也只要查 `tags` 一張表。
- `versions`、`attachments`、`note_tags` 沒有自己的 `user_id`，RLS 一律推導自所屬的筆記，避免兩邊的擁有者資訊不一致。
- `updated_at` 由 trigger 維護，前端傳什麼都會被蓋掉。樂觀鎖靠 `update ... where id = ? and updated_at = ?`，影響列數為 0 就是有衝突。

## 開發

```bash
npm install
cp .env.example .env.local   # 填入 Supabase 專案的 URL 與 publishable key
npm run dev
```

資料表要在 Supabase 的 SQL Editor 依序執行 `supabase/migrations/0001_init.sql`、`0002_storage.sql`。
環境變數還沒設定時首頁會顯示設定說明，dev server 照樣跑得起來。

專案結構：

```
src/app/          頁面與 layout
src/components/   UI 元件
src/lib/env.ts    環境變數
src/lib/supabase/ browser / server client 與資料庫型別
src/proxy.ts      session 更新與樂觀導向（Next 16 的 middleware）
supabase/         資料庫 migration
```

技術細節上有兩點跟大部分教學文章不一樣，翻文件時要留意：

- Next.js 16 把 `middleware.ts` 改名為 `proxy.ts`，Supabase 官方範例還是舊寫法。
- Next.js 明確建議 proxy 不要當成唯一的授權關卡，所以頁面與 Server Action 各自還要再呼叫一次 `supabase.auth.getUser()`。

## 測試

```bash
npm run check     # typecheck + lint + test
npm test          # 只跑測試
```

用 `node --test`，沒有額外的測試框架 —— 要驗的是幾條純函式與 remark 的解析結果，
為此拉進 Jest 或 Vitest 不划算。

[`tests/markdown.test.mjs`](tests/markdown.test.mjs) 共 16 項，涵蓋：

- `==重點==` 在一般段落渲染成 `<mark>`，顏色後綴變成 `data-hl`
- `if a == b` 這類比較式不被誤判
- 行首四個空白依標準變成程式碼區塊；兩個空白仍是段落
- 程式碼區塊（縮排式、圍欄式）與行內 code 裡的 `==重點==` 都不解析
- GitHub 式 callout 正確轉換，普通引用不被誤判
- `classifyIndent` 的六種情境：清單、有序清單、待辦、跨行選取、一般段落首次縮排、
  接近四格時擋下、tab 字元當四格算、空行

測試直接 import `.ts` 原始碼（Node 的型別剝離），不需要先編譯。
